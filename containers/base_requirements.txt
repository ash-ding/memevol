# Requirements for the forge eval-base image.
#
# TWO kinds of code run in a container built from this file:
#   * a forge-evolved harness — writes its own memory system against whatever
#     is here, and declares anything else in its own requirements.txt;
#   * a PACKAGED HARNESS BASELINE (tools/package_baseline.py) — a vendored
#     method with a pinned dependency set of its own.
#
# The heavy half is therefore pinned to what the baselines pin (their uv.lock
# files agree on these after the CUDA 12.4 switch), so a packaged baseline's
# requirements.txt installs a few megabytes of its own extras instead of a
# second multi-gigabyte stack on top of a nearly identical one. Diverging
# would not be wrong — pip would fix it up per harness — just slow and large,
# for every baseline, every time.
#
# Deliberately NOT pinned: everything an evolved harness might want fresher,
# where a delta install is cheap (openai, anthropic, the small utilities).
#
# Two outliers this cannot serve from one image (see each baseline's README):
#   hipporag2  torch 2.5.1 + transformers 4.45.2 + pydantic 2.10.4 — its
#              delta rebuilds torch, ~2.5 GB.
#   lightmem   transformers 4.57.6 (it pins <5 for its topic segmenter) —
#              a small downgrade, torch untouched.

# --- LLM APIs (small wheels; a baseline pinning an older openai is cheap) ---
# Upper bound, not a pin: common/openai_usage.py records a vendored method's
# token usage by patching the SDK's resource classes, and it no-ops QUIETLY
# when it cannot find them — a major SDK release could therefore turn token
# accounting into silent zeros at the next image rebuild. 3.15.0 is what this
# image was built and tested with (tests/test_openai_usage_shim.py passes
# inside it); raise the bound deliberately, after re-running that test.
openai>=1.107,<4
# [vertex] extra pulls google-auth — required for common/llm.py's Claude-via-
# Vertex transport (MEMEVOL_ANTHROPIC_TRANSPORT=vertex) inside the eval
# container.
anthropic[vertex]>=0.116
claude-code-sdk>=0.0.25
tiktoken

# --- Local models: pinned to the fleet ---
# torch comes from PyTorch's CUDA 12.4 index (see eval-base.def). PyPI's
# Linux wheels now bundle CUDA 13, which needs NVIDIA driver >= 580; penguin
# runs 550. A cu124 build also uses the GPU when one is bound (`gpu: true`),
# and falls back to CPU when none is.
